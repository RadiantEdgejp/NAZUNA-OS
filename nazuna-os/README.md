# nazuna-os

## 目的
nazuna-os は、AI社員の定義・運用手順・成果物テンプレート・DBスキーマを Git 管理し、レビュー可能な形で改善を継続するための初期骨格です。

## やること
- PC非依存で運用できること（環境差分を最小化する）。
- 社員=Git として、役割・行動規範・手順をバージョン管理すること。
- 資産=DB として、知見・ログ・実行履歴を永続化すること。
- 深掘りは 1 件に集中して実行すること。
- ループは最大 3 回までで打ち切り、次アクションを明確化すること。
- API はコード変更・デプロイのみ許可制（許可制）で実行すること。
- 全実行でログ記録を必須とすること。
- 週次改善を実施し、運用を継続的にアップデートすること。

## 禁止
- ローカルPC固有設定への過度な依存。
- Git未管理の運用ルール追加。
- ログなしの運用実行。

## 入出力
- 入力: 組織要件、運用課題、改善提案。
- 出力: 役割定義、プロトコル、テンプレート、Runbook、DB定義。

## 成功条件
- 変更差分がPRでレビュー可能である。
- 役割・手順・DBが一貫した運用基盤として利用できる。

## ディレクトリ構成
- `org_os/`: 憲章、役割定義、プロトコル、テンプレート
- `runbooks/`: 日次運用と移行手順
- `db/supabase/`: 初期スキーマとRLSポリシー
